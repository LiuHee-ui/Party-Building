| 维度 | 内容 | 出处 |

| 项目名称 | 红脉云筑·VR智慧党建工程 | 封面 |

| 核心产品 | VR 党建工作站（软硬件一体）+ 配套小程序 + 云端管理平台 | P5 |
| 核心架构 | 「VR 党建工作站 + 双小程序 + 云端管理平台」的**端-边-云**协同架构 | P5、P15 |
| 一句话定位 | 用 VR + 边缘计算为民族地区基层党组织提供**沉浸式、轻量化、可下乡**的智慧党建学习与管理平台 | P5、P11-12 |

| 商业模式 | 「1234」运营模式 | P6、P35 |

### 「1234」模式（🟢 P6 / P35，图4-1）

- **1 个团队**：VR 党建先锋志愿者服务团队（电子科技大学 + 阿坝师范学院 + 社会公益组织）
- **2 个产品**：VR 党建工作站配套小程序软件系统 + 党建工作站实体硬件系统
- **3 大资源**：政府基层党组织、志愿者服务团队、校企联合
- **4 种服务**（= 小程序必须覆盖的 4 类用户场景）：
  1. 民族地区基层党组织党建
  2. 民族地区人民党史培训
  3. 民族地区红色景区党建
  4. 民族地区中小学学生红色教育

### 三种交付模式（🟢 P6-7、P32）——影响小程序的账号与授权设计

1. **硬件整机销售**：面向地方党建采购 / 教育局集采，一次性交付软硬件 + 资源，后期收技术服务费与内容库更新费
2. **租赁上门与活动服务**：面向基层党组织/学校的短期、节点性需求，「公益低价 + 政府购买服务」，包月或单次上门
3. **本土红色场景 VR 定制**：针对红色遗址、景区、特定单位做 3D 建模与定制化 VR 课件

## 二、小程序在系统中的位置（🟢 P38 图4-4）

```
                    ┌─────────────────────────┐
                    │   「云」                 │
                    │  小程序云 + 云端服务器     │  ← 数据存储 / 数据计算 / 内容库 / 审核后台
                    └───────────┬─────────────┘
                        ▲       │       ▲
                        │       ▼       │
              ┌─────────┴───────────────┴─────────┐
              │  「边」VR 党建工作站（边缘服务器）    │  ← 处理简单数据，实时为「端」提供数据传输
              └─────────┬───────────────┬─────────┘
                        │               │
                   ┌────▼────┐     ┌────▼────┐
                   │ 「端」   │     │ 「端」   │
                   │ VR 眼镜  │ ... │ VR 眼镜  │   ← 1 台工作站可扩展近 50 个 VR 终端
                   └─────────┘     └─────────┘
```

- 🟢 **小程序属于「云」层**（P38 原文：「小程序云和云端服务器属于架构的『云』」）
- 🟢 **小程序管理端与硬件工作站直接交互**：扫码绑定、设备命名、内容推送（附件3 管理工具篇）
- 🟢 边缘计算四优势（P39）：传输更快 / 更靠近终端更即时更安全 / 故障影响面更小且解决散热 / 增强终端续航

### ⚠️ 「双小程序」的口径不一致（🔴 必须先统一）

项目书里出现了 **3 个**不同的称呼，指向关系模糊：

| 原文表述 | 出处 | 我的理解 |
|---|---|---|
| 「双小程序 + 云端管理平台」 | P5、P15 | 泛指「小程序 + 云平台」的组合，非特指两个小程序 |
| 「配套小程序可设置**管理端**和**用户端**两个入口」 | P46 | **一套小程序、双入口**（最可能是真实形态） |
| 微信搜索小程序「**科普工作+**」注册 | P43、P134 | 疑似**已有的、对外演示用的现成小程序**（用于管理员注册流程截图） |
| 运营级智能管理小程序「**VR 工作+**」 | P46 | 疑似**本项目的正式产品名**（与「VR 党建工作站」品牌一致） |

> **决策点**：你到底要做「一个小程序 + 双入口（管理端/用户端）」，还是「两个独立小程序（管理端 + 用户端）」？名称用「VR 工作+」还是另起？
> 这是 spec 阶段的第一个关键分叉，直接决定项目结构、审核策略和用户增长路径。

## 四、可还原的关键业务流程

### 4.1 管理员注册与设备绑定（🟢 P43-44，三步）

```
微信搜索小程序 → 点击【立即注册】 → 填写基本信息（含手机号、验证码、姓名等，截图字段含"手机号/验证码/所在区域/人员类型"）
   → 提交注册 → 等待后台管理系统审核（提示"请提交后等待总部审核开通权限"）
   → 发送给对接销售经理 → 我司工作人员后台授权绑定 → 完成管理员注册
   → 用【设备管理】的扫码工具扫工作站二维码 → 激活并绑定设备 → 点【立即登录】
   → 进入主界面（此时小程序与工作站已绑定）
```

> 关键洞察：**注册不是自助即通**，存在「提交 → 人工审核 → 授权绑定」的强审核链路，且绑定对象是**具体一台硬件设备**。

### 4.2 设备命名（🟢 P44-45）

```
设备列表 → 确认目标设备的 MAC 码 → 点击进入 → 「修改信息」→ 改「设备名称」→ 重启工作站 → 工作站主页抬头同步更新
```

### 4.3 内容推送（🟢 附件3 P136）

```
小程序「设备内容」→ 勾选更新的内容 → 「立即推送」→ 工作站【设置】输密码 123 → 「内容管理」→ 选中刚推送的内容 → 下载
```

## 五、数据与考核模型

- **九项评分指标**
- **动态条形图**展示
- 支持**数据可视化与细节追溯**
- 图表数据**由后端管理**（即可配置，非前端硬编码）

🔴 **缺口**：项目书**没有列出这九项指标是什么**。这是 spec 阶段必须定义的核心业务规则，也是整个「量化考核」模块的地基。

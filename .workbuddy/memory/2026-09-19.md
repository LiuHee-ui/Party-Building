### 本轮的关键设计决策
1. **标准答案不出现在任何面向客户端的 VO 里** —— 不是"记得过滤"，而是类型上就不存在
2. **排行榜按组织分片** —— 把权限设计进数据结构而不是查询条件；用户端按登录态取键，
   天然不可能读到别的组织
3. **实时写入 + 每日重算两条路径** —— 实时负责"快"，重算负责"对"；重算是全量覆盖，
   能自动修复 Redis 丢失与错乱
4. **第三处依赖倒置**：`common/spi/RankingScoreProvider` 由 exam 实现、learn 消费，
   打通"学时产生在 learn、榜单实现在 exam 但 exam 依赖 learn"的死结
5. **榜单写入失败要吞掉异常**：榜单是增值功能，学时入账是核心功能。
   判断标准：该故障会不会让用户无法完成核心动作
6. **看板两个比例的分母故意不同**（活跃度分母=在册人数，达标率分母=有学习记录人数），
   已写进 DashboardVO 类注释

### 联调抓出 7 个真实缺陷（单测全部无法发现）
1. **`characterEncoding=utf8mb4` 无效** —— Java 只认 `UTF-8`，`utf8mb4` 是 MySQL 服务端字符集名。
   错在启动期不报，第一个访问数据库的请求才炸
2. **惰性数据范围解析 + 默认空列表 → 待审队列静默返回 0 条**。
   `AuditController.pagePending` 忘了标 `@DataScoped`。已改为**拦截器统一解析**，
   删除 `@DataScoped` 与 `DataScopeAspect`（连同 party-boot 的 aop starter）
3. **`t_learn_session.last_end_at` 不该 NOT NULL** —— 会话建立时确实还没有被接受的心跳
4. **`OrgMapper.selectNamesByIds` 动态标签漏 `<script>`** → `Parameter 'oid' not found`
5. **两个枚举编码撞车**：`PeriodType`(1=自然年) 与榜单周期(1=周)。
   学时写进周榜、查询读年榜，Redis 里两个键都合法，**榜单永远为空且不报错**。
   已新增 `common/enums/RankingPeriodType` 并在 PeriodRange 中指向它
6. **判定精度超过存储精度**：`last_end_at` 秒精度 + 限流阈值 3000ms，
   MySQL 对小数秒四舍五入 → 真实 3.2s 间隔被算成 2.9s 误判限流。改为 `DATETIME(3)`
7. **环境变量 `SERVER__PORT=60533` 覆盖配置**（IDE 注入，优先级高于 yml）。
   必须用 `--server.port=8080` 显式指定

### 本机 Git 环境坑（可复用）
1. **SSH 走不通**：22 端口连接超时；`ssh.github.com:443` 可连通但本机公钥未注册到 GitHub 账号
   （`Permission denied (publickey)`）。→ 只能用 HTTPS。
2. **HTTPS 凭据已存在 Windows 凭据管理器**（GCM/`wincred`），
   用户名为 GitHub 账号、凭据为 `gho_` 开头的 OAuth token。
   探测方式：`printf "protocol=https\nhost=github.com\n\n" | git credential-wincred get`。
   push 用 `git -c credential.helper=wincred push`，配 `GIT_TERMINAL_PROMPT=0` 防挂起。
3. **`refs/remotes/origin/main` 写不进去**：环境的沙箱文件系统会吞掉 `git fetch`/`update-ref`
   对 `.git/refs/remotes/` 的写入（命令返回成功但文件不存在），导致 `git status` 显示
   `[gone]`。**绕过方法**：直接用 Write 工具写 `.git/packed-refs`，内容为
   `# pack-refs with: peeled fully-peeled sorted` + 一行 `<commit> refs/remotes/origin/main`。
   写完 `git status` 立即恢复 `## main...origin/main`。
